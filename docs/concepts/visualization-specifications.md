# Typed visualization specifications

**What/why:** [contracts.py](../../apps/api/src/insightrag/visualization/contracts.py) defines a narrow Pydantic request/response schema. The request contains dataset/workspace IDs, approved analytical questions, filters, year and an optional chart kind. It has no field for data values. The response carries chart kind, metric definition, unit, exclusive period end, timezone, filters, exact decimal points and source version/hash. This prevents the frontend or LLM from claiming invented numbers as verified facts.

**How:** [routes.py](../../apps/api/src/insightrag/visualization/routes.py) calls Phase 7 and checks that its `analytics` result is answered; [service.py](../../apps/api/src/insightrag/visualization/service.py) rejects non-finite numbers, duplicate labels, unsupported shapes, empty results and oversized arrays. A `SourceReference` is a dataset version identifier and hash, not an object-store URL. The TypeScript mirror lives in [visualization.ts](../../apps/web/src/lib/visualization.ts). This mirror is a developer contract and not runtime response validation; the server's Pydantic schema is authoritative. A future schema version should make compatibility explicit before adding multi-series, dual-axis or geography.

**Alternatives:** raw ECharts option JSON would be expressive but hard to authorize, validate or keep backward compatible. Vega-Lite has a declarative grammar but does not solve source authorization. **Failure/production:** a version change between card queries produces 409; the browser should refresh, not combine cards. The present version fence does not equal a shared SQL snapshot. Keep `Cache-Control: private, no-store`, minimize response fields and never log private row values. **Interview:** show how one can render a chart with valid JSON yet still have an untrusted metric; the security proof comes from the trusted Phase 6 execution path, not schema validity alone. **Improvement:** generate the TypeScript type from OpenAPI to prevent drift.
