## Concrete example

An authorized admin uploads `report.txt` containing `Delhi revenue declined`. The upload has a valid JWT and `X-Organization-ID`, passes resource `upload`, text UTF-8 and scanner checks, and receives a 202 response with job/version UUIDs and a SHA-256. The worker validates the signed claims and the current DB grant again. The TXT parser emits `line:1`; chunking emits one chunk with that locator and a token count; the embedding adapter returns exactly 1536 finite floats. A transaction inserts that chunk and changes `active_version`. A later evidence read retrieves `line:1` only if the current user can `read` the active resource. A duplicate SHA on the latest version returns `duplicate` without another DB version. An older job returns `stale` if a newer version was reserved.

If a page has no digital text and OCR is disabled, the parser raises `ParseRejected`; the job becomes failed and the prior active version remains. If the provider returns 1535 coordinates, `validate_vectors` rejects it and no partial chunk set publishes. If the worker dies during the indexing transaction, PostgreSQL rolls it back. A fresh operator dispatch may replay the job, subject to current policy and the attempt limit.

## Non-obvious code and constraints

`set_config(..., true)` uses transaction-local PostgreSQL settings so a reused pooled connection cannot carry the previous tenant's identity. RLS is the database backstop, not a replacement for API authorization. The reservation function locks the resource before comparing the latest hash/version; two concurrent uploads serialize there. The publication function locks both job and resource and compares `latest_version` plus organization `policy_revision` to reject stale work. `ingestion_chunks` can have staged rows invisible to readers until `active_version` switches. The HNSW index is physical indexing, not an authorization boundary; vector queries must still filter by current tenant/resource ACL.

Known code-level limits: 50 MiB request buffering and in-process parser expansion; CSV numeric strings are preserved, not semantically typed; XLSX floating cells reflect spreadsheet numeric representation; document-level model profile is recorded but tokenizer compatibility is fixed; no standalone retrieval endpoint; scanner/provider/storage integrations were not live-tested. The next redesign should prioritize sandboxed parsers, streaming object upload, provider-aware token profiles, bulk inserts, and a transactional outbox measured against real workload.
