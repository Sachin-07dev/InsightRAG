# Chart selection and honest scales

**What:** A chart maps typed dimensions and measures to visual marks. `build_view` in [service.py](../../apps/api/src/insightrag/visualization/service.py) uses monthly `YYYY-MM` dimensions for a line, one total for a KPI, and multiple categorical values for a bar; explicit table preserves precise comparisons. **Why:** the data shape, not an LLM's aesthetic choice, determines supported encodings. A line implies ordered time; a bar compares categories. A stacked chart requires multiple compatible series at the same grain, scatter needs two paired numeric measures, and a map requires validated geographic identifiers or coordinates. Phase 6 does not provide those contracts, so the engine rejects them.

**How:** Phase 6 aggregates signed revenue in SQL and returns decimal strings. The view builder copies those strings without summing. A monthly line must contain ordered, consecutive, valid months; missing months produce a clarification error instead of a misleading connected line. ECharts converts to JavaScript numbers for screen coordinates, while the table retains exact decimals. Bars with nonnegative values start at zero; negative signed revenue is allowed and the renderer must show a zero crossing. Null is shown as undefined, not zero. The axis unit comes from the analytical result; mixed currencies are never combined. A tooltip supports inspection, but source version, period and filter text are always visible. Truncating a bar axis, hiding a negative period, or using category labels as geographic coordinates would mislead.

**Production:** a high-cardinality bar chart becomes unreadable and costly. The 500-row server cap is a safety limit, not a good default presentation limit. Measure latency and user comprehension, then add server-approved top-N and pagination with totals. Geographic maps require an authoritative geocoding contract, map asset licenses and privacy review. **Alternatives:** Plotly or Vega-Lite provide other grammar and interaction models; simple HTML tables can be best for exact audit tasks. **Interview:** explain why a monthly line is valid but a scatter plot cannot be built from one revenue measure. **Improvement:** make chart recommendations depend on an explicit semantic-layer dimension type, not a month-label pattern, after Phase 6 exposes one.
