# Technology choices, alternatives and change triggers

The decisions below are **proposed for owner review** in [ADR 013](../../architecture/decisions/013-versioned-ingestion.md). “Faster” and “cheaper” are workload-dependent; no benchmark is claimed.

| Need | Selected and where | Alternative | Tradeoff / evidence to change |
| --- | --- | --- | --- |
| Web upload/progress | FastAPI REST POST plus GET polling in [routes](../../../apps/api/src/insightrag/ingestion/routes.py) | WebSockets or SSE | One upload and infrequent progress updates do not require a persistent connection. Polling costs repeated HTTP requests; at thousands of active clients, measure request load and consider SSE with authenticated reconnect. WebSockets are useful for bidirectional collaborative sessions. |
| Durable background work | Redis/Celery in [worker](../../../apps/api/src/insightrag/worker.py) plus PostgreSQL job record | FastAPI BackgroundTasks, RabbitMQ, managed workflow | BackgroundTasks are tied to an API process and weak for retries/recovery. Redis is already present and simpler locally, but broker acknowledgement is at least once and message loss can happen; DB job plus redispatch recovers it. RabbitMQ adds routing and queue durability controls when needed. |
| PDF extraction | PyMuPDF in [parsers](../../../apps/api/src/insightrag/ingestion/parsers.py) | Docling, pdfplumber, Unstructured | PyMuPDF gives page/block text and OCR hook with relatively small integration surface; it can miss semantic tables/layout. Docling may improve complex-layout fidelity but adds models, CPU and packaging cost. Choose from a labeled extraction-quality corpus, not popularity. |
| OCR | PyMuPDF Tesseract hook, opt-in | Managed OCR / Docling pipeline | Local OCR avoids sending private pages to a third party but is CPU-heavy and language/quality dependent. Empty scanned pages fail if OCR is disabled/unavailable. Measure character/word error and table accuracy before enabling broadly. |
| DOCX/XLSX | python-docx and openpyxl | LibreOffice conversion, Apache POI service | Direct Python parsing preserves body/table/worksheet structure without conversion services. It does not establish rendered DOCX page numbers. Very large OOXML still needs sandbox/memory limits. |
| Tokenization/chunking | Pinned cl100k table; source-segment windows in [chunking](../../../apps/api/src/insightrag/ingestion/chunking.py) | Word/character/fixed/recursive/semantic splitting | Token windows respect provider budgets and page/table locators. They can split sentences or tables; semantic chunking needs a model, cost and evaluation. Change chunk size/overlap using labeled retrieval recall and citation accuracy. |
| Embeddings | Operator-configured HTTPS OpenAI-compatible 1536D adapter in [embeddings](../../../apps/api/src/insightrag/ingestion/embeddings.py) | Local model, different hosted provider | Batching reduces per-request overhead; hosted API incurs latency, rate limit, cost and residency review. Model change requires a new compatible index/profile and reembedding; mixing dimensions or spaces invalidates similarity. |
| Vector search | PostgreSQL pgvector HNSW in [migration](../../../apps/api/migrations/versions/0003_ingestion.py) | FAISS, dedicated vector DB | One transactional database simplifies version fencing and RLS. FAISS is an in-process library with no native tenant SQL policy or durable metadata transaction. Dedicated service can help measured scale/latency but adds consistency and operational boundaries. HNSW improves approximate search latency at RAM/build cost and may trade recall; exact scan remains an evaluation baseline. |
| Object storage | S3 API + KMS in [storage](../../../apps/api/src/insightrag/ingestion/storage.py) | Filesystem, DB bytea, Azure Blob | Object storage handles durable large blobs and regional placement; bucket/IAM/KMS/network controls must be configured. A local filesystem is simpler for tests but not multi-replica durable. Database blobs inflate backup and connection workload. |
| Structured rows | PostgreSQL JSONB with region RLS, no embeddings | Pandas or DuckDB staging; warehouse | This preserves rows and source provenance while Phase 6 defines typed metrics. JSONB is not a complete analytical model. Once larger datasets or complex joins are measured, stage typed tables/DuckDB/warehouse under enforced row entitlements. Never compute exact totals from vector neighbors. |

Security, cost, complexity and reliability are linked: a new database/service can improve one latency curve while creating extra consistency, tenancy, backup and on-call work. Record measured recall, latency, ingestion throughput, memory, per-tenant cost and failure modes before a replacement.
