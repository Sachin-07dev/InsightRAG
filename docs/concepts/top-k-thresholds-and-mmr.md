# Top-K, thresholds and maximal marginal relevance

Retrieval Top-K is the number of candidates kept, unrelated to a generator's token-sampling Top-K. `Settings` bounds dense and sparse pools at 20 each, fused pool at 20 and final context at 6. Larger K can improve recall but increase noise, rerank cost and context stuffing; smaller K may miss the needed evidence. `Precision@K = relevant retrieved/K`; `Recall@K = relevant retrieved/all relevant`. For two relevant chunks in a five-chunk corpus, retrieving one relevant among three gives P@3=1/3 and R@3=1/2.

A top result may be irrelevant, so the optional `retrieval_max_cosine_distance` discards dense candidates beyond a calibrated cutoff. Cosine **distance** decreases with relevance; similarity increases. The default is unset because model, corpus and chunking change distributions. Choose a cutoff using labelled positive/negative distances on a held-out permission-aware set, then inspect abstention and false-negative rates. Sparse hits still enter fusion when dense is cut. Never transplant a threshold between embedding models without reevaluation.

`maximal_marginal_relevance` in `retrieval/ranking.py` greedily selects `argmax_d [λ sim(q,d)−(1−λ)max_{s∈S}sim(d,s)]`, with λ=0.7 when explicitly enabled. Example: after selecting A, duplicate B has query similarity 0.9 and similarity to A 0.99; diverse C has 0.8 and 0.2. At λ=0.5, B scores −0.045 while C scores 0.30, so C wins. This may omit a near-duplicate that contains a crucial distinction; evaluate evidence coverage and answer quality, not only novelty. All candidate vectors must use the same model and metric. Context budget can still exclude an MMR-selected chunk.
