# Dashboard lifecycle and interaction

The [browser page](../../apps/web/src/app/dashboard/dashboard-client.tsx) holds token, organization, workspace, dataset, year and region in component state. Submitting sends six questions through the same-origin [proxy](../../apps/web/src/app/api/dashboard/route.ts) to the [dashboard route](../../apps/api/src/insightrag/visualization/routes.py). Every card repeats current membership, workspace/resource ACL and row-level security checks in existing services. A denied card aborts the whole request. Browser state is ephemeral; a reload requires credentials again. The proxy stores no response or token and cannot override authorization.

Tooltip, zoom and legend visibility are presentation interactions. A year/region filter is a business query and always executes a new authorized request; it never filters a cached national total in the browser. Drill-down to transaction rows is not implemented because the Phase 6 API exposes only governed aggregates. Saved dashboards, shared URLs, PDF reports and server-side exports would need resource ACLs, retention/deletion propagation and revocation checks. Do not generate a share URL by serializing the current result.

Operationally, sequential multi-card queries are simple and keep source provenance per card, but latency adds. A true shared snapshot would require a trusted batch query service; parallel requests alone could worsen connection pressure and version races. Use measured p95 latency, pool usage and denied-card behavior to decide. Screen-reader users receive an HTML table and textual metric metadata as a stable fallback to SVG. Test responsive behavior in browsers at multiple widths; CSS responsiveness alone is not a completed accessibility audit.
