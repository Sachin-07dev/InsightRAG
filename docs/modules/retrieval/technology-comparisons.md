# Alternatives, production tradeoffs and change evidence

| Choice | What/why/how here | Alternatives and evidence for change |
| --- | --- | --- |
| PostgreSQL pgvector cosine | Phase 4 already stores fixed 1,536-dimensional vectors; Phase 5 queries `embedding <=> vector` with RLS and active-version predicates. HNSW reduces candidate scan work but approximate recall can fall under restrictive filters. | Exact pgvector scans give a recall baseline but cost more CPU; IVFFlat needs trained lists and probe tuning; a dedicated vector engine adds synchronization and ACL duplication. Benchmark exact-vs-ANN recall and p95 by tenant before replacing. |
| PostgreSQL full-text GIN + `ts_rank_cd` | An inverted index finds rare exact tokens that semantic vectors may miss; cover-density ranking values are not BM25. English stemming is selected because the initial corpus profile is English. | BM25 search engines can improve length-normalized lexical ranking but add a service; trigram search helps typos, not semantic paraphrases. Change when labelled exact-ID and multilingual queries demonstrate a gap. |
| RRF | Rank-only `Σ1/(60+r)` avoids comparing different score scales; deduplicates by immutable source-version-position key. | Weighted score fusion needs calibration per model/corpus; dense-only and sparse-only are simpler but lose complementary recall. Tune weights and rank constant only against held-out labels. |
| MMR | Greedy `λsim(q,d)−(1−λ)max sim(d,s)` removes near-duplicates when enabled. | Pure top-K maximizes rank relevance; cluster/parent retrieval may retain more context. Measure answer evidence coverage, not just diversity. |
| HTTPS score reranker | A separately configured adapter reranks at most a bounded candidate pool after ACL filtering; failure falls back to fusion. | Local cross-encoder can avoid external data transfer but needs CPU/GPU serving; API ranking incurs network cost and residency review. Select a real provider/model only after quality, latency, privacy and cost evaluation. |
| OpenAI-compatible JSON chat | A narrow `Generator` protocol and Pydantic contract provide swappable inference and bounded output. It is an API shape, not a provider endorsement. | Local model serving improves control/residency but requires model operations; extractive answers reduce hallucination but cannot synthesize complex comparisons. Compare on labelled faithfulness, cost and p95. |
| REST response | One bounded answer and structured errors fit HTTP request-response. | SSE streams tokens one-way with reconnection semantics; WebSockets support bidirectional state but add connection lifecycle. Add streaming only for measured user latency benefit, with citation finalization and disconnect tests. |
| Persistent owner-scoped conversation | RLS and current membership keep prior question available for follow-ups; stored citations retain version IDs. | Client-supplied history is easier to spoof; full semantic memory increases poisoning and stale-evidence risk. Add retention/purge and summaries only after policy and evaluation work. |

High load threats include DB pool exhaustion, HNSW/FTS latency, external provider rate limits, reranker queueing, context-window overflow, cost spikes and retry storms. Instrument stage timings and error classes without logging raw questions/chunks. A provider timeout returns 503, rather than retrying indefinitely inside one request. Managed secrets, egress allowlists, residency agreements, model-version pinning, quotas and production load tests remain deployment responsibilities.
