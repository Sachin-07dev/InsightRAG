# Exact analytics: formulas, periods and edge cases

For compatible rows, signed revenue `R=Σ revenue`, signed cost `C=Σ cost`, profit `P=R-C`, margin `M=100P/R` when `R≠0`, otherwise null. Regional contribution `100R_region/R_national` requires complete-region entitlement and a nonzero national denominator. Year growth `100(R_current-R_prior)/R_prior` is returned only for a **positive** prior baseline; absent, zero and negative baselines produce null pending approved business meaning. Missing current rows with a positive prior baseline yield `-100%`. [The fixed SQL](../../apps/api/src/insightrag/analytics/service.py) calculates aggregates in PostgreSQL `numeric(20,4)`; [the validator](../../apps/api/src/insightrag/analytics/ingestion.py) uses Python `Decimal` before insertion. Binary floats are inappropriate for financial totals.

Example: a 100.10 sale and -10.05 refund give signed revenue 90.05. If their signed costs are 40.00 and -4.00, cost is 36.00, profit 54.05, margin `100*54.05/90.05 ≈ 60.0222%`. The precise ratio is computed from totals, not from average row percentages. A refund is represented by negative revenue, while `returns` is a separate count; whether a real source system uses this convention must be approved. Null monetary cells are rejected for governed sales, avoiding silent `SUM` omission. Duplicate transaction IDs are rejected. Currency mixing requires clarification; conversion is not implemented.

The “previous three complete months” boundary is `[first day three months before current month, first day of current month)` in the organization's reporting timezone. An organization-local date of 19 February 2026 selects November 2025 through January 2026. The source date is already a local business date; UTC timestamp-to-local conversion is not performed. Incomplete historical months are not yet detected. `GROUP BY` computes each dimension; a future `HAVING` threshold or window rank needs explicit semantics. SQL CTEs/window functions can express YoY in one statement, but two bounded aggregate statements keep this implementation simple; both use the same transaction and policy context.
