# Sparse retrieval, PostgreSQL full-text search and BM25

**What/why.** Sparse lexical search indexes terms rather than dense semantic coordinates. An inverted index maps a token to rows containing it, making `INV-42`, names, error codes and rare financial identifiers retrievable even when an embedding blurs them. Migration `0006_retrieval.py` adds a GIN expression index on `to_tsvector('english',text)`; `retrieval/repository.py` uses `websearch_to_tsquery` and `ts_rank_cd`. PostgreSQL's built-in rank is cover-density ranking, **not BM25**. English stemming and punctuation processing can still damage exact identifiers; evaluate raw-ID search before claiming exact-match coverage.

**Math/how.** TF counts occurrences; IDF downweights terms common across documents. A common BM25 formulation is `Σ IDF(t) × [f(t,d)(k1+1)]/[f(t,d)+k1(1−b+b|d|/avgdl)]`. Here `f` is term frequency, `|d|/avgdl` length ratio, `k1` controls saturation and `b` length normalization. With `k1=1.2`, `b=0.75`, a document of average length and `f=2`, the TF factor is `2×2.2/(2+1.2)=1.375`; multiply by the term's IDF. This **explains BM25**, but the implementation computes `ts_rank_cd` instead, whose cover density rewards close matching terms. Neither raw BM25 nor `ts_rank_cd` score should be added to cosine distance.

**Implementation/production.** PostgreSQL parses query text to a `tsquery`, matches against `tsvector` through GIN, then ranks matched chunks. The SQL's tenant/workspace/active-version/ACL predicates and RLS restrict candidates before their content leaves the DB. FTS can miss synonyms, non-English morphology and typos; dense retrieval complements it. Alternatives: a dedicated BM25 service can offer richer ranking, language analyzers and facets but requires synchronized deletion/permissions; trigram indexing improves typo tolerance yet can be expensive. Measure recall and latency for exact identifiers, multilingual content and ACL filters before adding either. Monitor index growth and query plans; keep query length and candidate counts bounded.

**Interview/improvement.** Explain an inverted index, TF saturation, IDF and length normalization; distinguish PostgreSQL rank from BM25. To debug a missing invoice ID, inspect tokenization with `to_tsvector`/`websearch_to_tsquery`, then verify version and ACL filters before changing ranking.
