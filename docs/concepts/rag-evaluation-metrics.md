# RAG evaluation metrics and experiment design

`retrieval/evaluation.py` implements bounded ranking metrics on labelled relevant IDs. At K: `P@K=hits/K`; `R@K=hits/|relevant|`; hit rate is 1 if any hit; `RR=1/rank(first relevant)`; `AP=Σ_{relevant rank i}P@i/|relevant|`; `MAP=mean(AP)`; `DCG@K=Σ(2^grade_i−1)/log2(i+1)` and `NDCG=DCG/ideal DCG`. For ranking `[wrong,A,B]` with `{A,B}` relevant at K=3: P=2/3, R=1, RR=1/2, AP=`(1/2+2/3)/2≈0.583`. NDCG discounts the first-position error. If no relevant document exists, recall/AP/NDCG are defined as 0 in this implementation; abstention is evaluated separately.

Candidate coverage asks whether the relevant chunk entered the pool before reranking. ANN recall compares approximate search against an exact authorized vector scan, not against human relevance labels. Retrieval latency covers embedding, SQL, fusion and reranking separately. Generation checks answer correctness, faithfulness to cited excerpts, relevance, citation accuracy/coverage, appropriate abstention, hallucination, permission compliance, end-to-end latency, tokens and cost. Exact string matching is brittle; LLM-as-judge can share model biases and may miss subtle financial errors. Human adjudication on a stratified sample remains essential.

Use synthetic permission-aware cases for facts, paraphrases, IDs, multi-document conflict, no evidence, revoked/deleted versions, injection, numerical handoff and follow-ups. Keep a held-out test split and record dataset, embedding/generation/reranker model versions, dimensions, index settings, chunking profile, software versions and seed. Compare one variable at a time: dense/sparse/hybrid, K, threshold, MMR, reranker, rewrite, context order, models, chunking, exact/ANN. Record quality with p50/p95/p99 latency and provider usage; do not turn the tiny ranking fixture in `scripts/evaluate-retrieval.py` into a production performance claim. [Actual checks](../testing/retrieval-evaluation.md) distinguish executed from pending experiments.
