# Implementation walkthrough

`QueryRequest` in `contracts.py` caps a question at 2,048 raw characters and at most 32 explicit resources; `prepare_query` in `query.py` normalizes Unicode to NFC, collapses whitespace, rejects control characters and caps normalized text at 1,000 characters. This is normalization, not semantic rewriting. The conservative analytics regex sends likely aggregates to `analytics_required`; false positives/negatives are a known limit. `resolve_followup` appends the prior question only for short explicit pronoun references. It never removes named entities, dates or amounts. A future LLM rewrite must preserve these constraints and be evaluated against query drift.

`answer_query` in `service.py` first validates workspace and any explicit resource through current database policy. It reads only a previous question from an owner-scoped conversation, then asks the Phase 4 `Embedder` for one 1,536-dimensional query vector. The returned count, dimensions, finite values and nonzero norm are checked. An unavailable provider returns 503. The configured model ID is used in both candidate searches; mixed embedding models cannot silently share a distance scale.

`retrieve` in `repository.py` executes two parameterized SQL queries. Dense uses `embedding <=> CAST(:vector AS vector)` where lower means closer under cosine distance; the HNSW index is compatible with `vector_cosine_ops`. Sparse uses `websearch_to_tsquery('english',:query)` and `ts_rank_cd(to_tsvector('english',c.text),...)`; larger ranking values are better. A GIN expression index accelerates the match. The SQL joins `resources.active_version` and published `document_versions`, filters current tenant/workspace/kind/model/state, optional ID scope and `can_resource`. The runtime DB role also triggers RLS. The queries cap candidate counts and use deterministic tie breaks. Parsing an embedding text column is only requested for MMR.

`reciprocal_rank_fusion` in `ranking.py` sums `1/(60+rank)` for each channel, deduplicating on resource, version and chunk position. It never adds raw sparse and vector scores. Optional `maximal_marginal_relevance` greedily balances cosine query relevance against similarity to already chosen chunks. The optional API `CompatibleReranker` in `rerank.py` receives only authorized texts, validates one finite score per input, and falls back to fused order if unavailable. A local cross-encoder is not implemented.

`assemble_context` in `context.py` counts with the pinned `cl100k_base` tokenizer, reserves a configured context slice, deduplicates exact repeated chunk text per version, and labels evidence by SHA-256 of tenant/resource/version/position. Those labels are opaque but reproducible; they are not access credentials. A partial final chunk is allowed only if its decoded excerpt remains in the source text. The generated prompt in `provider.py` identifies evidence as untrusted and requests JSON with `answer`, `citation_ids`, `uncertainty`; schema validation bounds the response. The model is instructed to abstain and avoid numerical aggregates. Prompt instructions alone cannot prove faithfulness.

After inference, `verify_citations` rejects labels outside the selected evidence. `revalidate_evidence` rereads exact text with the same ACL and active-version constraints. The service locks and compares current policy revision, writes an owner/workspace conversation turn and audit event in one transaction, then returns only authorized citations. A revoked permission, deleted document, replaced version, invalid provider JSON or forged citation results in a structured error rather than a stale answer. The code does not independently prove that every natural-language claim is entailed by its cited excerpt; evaluation and reviewer feedback are required.
