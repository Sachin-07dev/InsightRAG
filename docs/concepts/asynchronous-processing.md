# Asynchronous processing and durable jobs

**WHAT/WHY.** A synchronous function blocks its caller until done; an `asyncio` coroutine yields at `await`, letting one thread run other I/O work. Concurrency means tasks overlap; parallelism means computations execute simultaneously on different cores. Python threads are useful for blocking I/O or native extensions, while CPU-heavy Python needs processes or native code that releases the GIL. In [the upload route](../../apps/api/src/insightrag/ingestion/routes.py), HTTP validation and authorization remain bounded. Parsing, OCR, embedding and indexing run in [the Celery worker](../../apps/api/src/insightrag/worker.py), not inside the response request. The parser call uses `asyncio.to_thread` to avoid blocking the worker event loop; worker process and task limits bound total runtime. Python `async` alone does not make OCR parallel.

**HOW.** The API commits a PostgreSQL `ingestion_jobs` row, then sends a signed JSON task through Redis. Celery workers reserve tasks; late acknowledgement means a crash may redeliver work. A PostgreSQL job is the acceptance ledger because queue delivery is not a database transaction. [The service](../../apps/api/src/insightrag/ingestion/service.py) checks current identity, job revision and resource grant before work and again before publication. Transient object/provider failures retry with short exponential delays; the same job version and primary keys prevent duplicate visible effects. A worker crash during SQL staging rolls back that transaction. A stale or failed job needs a newly signed operator redispatch. `queued` or old `running` jobs are operational alerts. No automated sweeper, lease, dead-letter queue or transactional outbox exists yet.

**Alternatives/production.** FastAPI `BackgroundTasks` is appropriate for short best-effort local work, not a durable OCR/embedding pipeline. RabbitMQ offers richer broker routing/acknowledgement policies but adds a service; Redis is reused here. A managed workflow engine could handle timers and reconciliation at larger scale. Backpressure needs queue length/age metrics, per-tenant concurrency quotas, separate OCR and embedding pools, and provider rate-limit budgets. Distributed locks alone do not ensure correctness after lease expiry; `latest_version` and policy revision are the fencing values. Monitor jobs by stage, attempts, age, timeout, provider 429, memory and publication result. See [worker code](../../apps/api/src/insightrag/ingestion/service.py) and [test plan](../testing/ingestion-tests.md).

**Interview/improvement.** Explain why `await` helps S3/provider I/O but not CPU-bound OCR; why at-least-once tasks need idempotent DB effects; and how a stale worker loses publication even after successful embedding. Move to an outbox and lease-based sweeper when lost-dispatch/running-age measurements justify it.
