# Phase 8 interview preparation

Each answer below connects to the actual implementation; all examples use synthetic data. The three major choices are ECharts/React rendering, typed specifications and numerical fidelity, and authorized dashboard composition.

## ECharts and frontend rendering

1. **Question:** Why choose ECharts for this dashboard? **Short answer:** It covers our line/bar interactions, SVG export, zoom and tooltip in one client library. **Deep explanation:** [chart-card.tsx](../../apps/web/src/app/dashboard/chart-card.tsx) creates and disposes one ECharts instance per card; a React effect synchronizes an imperative chart with declarative props. It still needs an HTML data table for exact values and screen-reader access. **Project example:** synthetic monthly Delhi revenue renders a line and exact table. **Follow-ups:** Why SVG? It scales cleanly and is exportable; when choose Canvas? Benchmark large series where SVG DOM cost grows. **Common mistake:** calling the chart library an authorization layer. **Alternative:** Plotly React or pure SVG. **Exercise:** profile rendering 500 monthly points and compare renderer cost.
2. **Question:** How do React and ECharts lifecycles interact? **Short answer:** Create after mount, update on verified prop change, dispose on cleanup. **Deep explanation:** `useEffect` depends on a typed view; `ResizeObserver` resizes the chart; cleanup prevents detached canvases/listeners. **Project example:** refreshing filters replaces cards. **Follow-ups:** What if Strict Mode mounts twice? Cleanup must be idempotent; what if the container width changes? Call `resize`. **Common mistake:** creating an instance on every render. **Alternative:** a maintained React wrapper. **Exercise:** write a browser test for repeated filter refreshes.
3. **Question:** How do tooltip and zoom affect metric correctness? **Short answer:** They should change presentation only. **Deep explanation:** Tooltips read values already returned by the API; zoom changes visible range, never totals. A business filter triggers a new server query. **Project example:** the six-card dashboard's year and region controls refetch. **Follow-ups:** Can client filtering show national contribution? No, that denominator needs Phase 6; when is local zoom safe? When it only clips visual coordinates. **Common mistake:** recalculating percentages in the browser. **Alternative:** server-driven interactions. **Exercise:** inspect network calls after a region change.
4. **Question:** Why keep an HTML table beside every chart? **Short answer:** It preserves exact decimal strings and is a dependable accessible fallback. **Deep explanation:** JavaScript numbers are binary floats, so plotting `100.1000` yields an approximate coordinate; [visualization.ts](../../apps/web/src/lib/visualization.ts) converts for ECharts only, while the table displays the original string. **Project example:** `100.1000` remains visible as such. **Follow-ups:** Could SVG text alone suffice? It lacks structured table semantics; how would huge tables scale? Accessible pagination with server-approved limits. **Common mistake:** claiming pixel locations are exact financial values. **Alternative:** table-only audit view. **Exercise:** compare chart tooltip and exact table for high-precision decimals.
5. **Question:** How should a chart export be secured? **Short answer:** Fetch authorized data first; apply export policy and understand downloaded files cannot be revoked. **Deep explanation:** the current client exports its authorized in-memory SVG/PNG after rendering. There is no persistent server artifact or shared link. **Project example:** button in [chart-card.tsx](../../apps/web/src/app/dashboard/chart-card.tsx). **Follow-ups:** What happens after permission revocation? Already downloaded files remain; how would server reports work? New ACL-governed artifacts with retention/deletion. **Common mistake:** treating a local image as dynamically revocable. **Alternative:** governed server export. **Exercise:** design a watermark and audit event for export.

## Typed specifications and data fidelity

6. **Question:** Why reject raw chart-option JSON from the client? **Short answer:** It can relabel or invent values and bypass our presentation rules. **Deep explanation:** [contracts.py](../../apps/api/src/insightrag/visualization/contracts.py) permits questions, scope and a narrow kind; [service.py](../../apps/api/src/insightrag/visualization/service.py) builds the points from verified Phase 6 rows. **Project example:** client cannot send `revenue=1,000,000`. **Follow-ups:** Does Pydantic alone prove authorization? No, Phase 6 ACL/RLS does; how to add a new chart kind? Version the schema and add shape/security tests. **Common mistake:** equating valid JSON with trustworthy data. **Alternative:** Vega-Lite grammar, still needing authorization. **Exercise:** submit an extra values field and verify it cannot affect output.
7. **Question:** Why does a line require monthly labels? **Short answer:** A line implies ordered progression, so arbitrary category order would suggest false trends. **Deep explanation:** `build_view` checks month-like labels before allowing a line. This is a baseline heuristic; a semantic-layer time dimension would be stronger. **Project example:** Delhi monthly revenue permits line; `Delhi`/`Mumbai` revenue does not. **Follow-ups:** Is `YYYY-MM` sufficient to prove time? No, validate calendars and metadata; how handle irregular time gaps? Preserve actual dates and gap semantics. **Common mistake:** connecting unordered categories. **Alternative:** bar or table. **Exercise:** test malformed `2025-13` labels.
8. **Question:** Why can the current engine not show a stacked chart? **Short answer:** One Phase 6 result has one approved metric series, while stacking needs compatible aligned series. **Deep explanation:** stacking arbitrary revenue and percentage units is invalid and can double count across grains. **Project example:** `build_view` rejects `stacked`. **Follow-ups:** What data contract is needed? Common dimension keys, multiple series and compatible units; what SQL risk arises? One-to-many joins multiply facts. **Common mistake:** duplicating one series into stacks for visual effect. **Alternative:** separate bars. **Exercise:** define a typed two-series result with provenance.
9. **Question:** When is a geographic chart valid? **Short answer:** Only when authorized data includes a reliable geographic key or coordinates. **Deep explanation:** a free-form `region` label is not a coordinate or map boundary. Geocoding and map assets have ambiguity, privacy and licensing implications. **Project example:** the sales schema has region text, so `geo` is rejected. **Follow-ups:** Could `Delhi` be geocoded automatically? Not without an approved location mapping; how handle nested regions? Use stable IDs and hierarchy. **Common mistake:** plotting names as locations without a geospatial contract. **Alternative:** regional bar chart. **Exercise:** design a region dimension table.
10. **Question:** How do you prevent misleading numerical axes? **Short answer:** Preserve unit and signed values, start nonnegative bars at zero, and make undefined distinct from zero. **Deep explanation:** the view carries a metric definition, unit and period, and the renderer chooses a zero baseline for nonnegative data. Financial signed revenue can be negative due to refunds. **Project example:** a `-4.2500` month remains negative. **Follow-ups:** Is a zero baseline mandatory for line? No, but disclose scale; what about mixed currencies? Require a single currency or approved conversion. **Common mistake:** averaging ratios or silently hiding negative points. **Alternative:** exact table. **Exercise:** inspect an export for axis labels and units.

## Authorization, dashboard systems and debugging

11. **Question:** Why re-run authorization for each dashboard refresh? **Short answer:** Permission or dataset state may change after the prior view. **Deep explanation:** [routes.py](../../apps/api/src/insightrag/visualization/routes.py) invokes Phase 7 for each card; Phase 6 checks current membership, workspace, ACL and RLS. **Project example:** a revoked user's next request is denied. **Follow-ups:** Is a valid JWT enough? No, it proves identity, not resource access; what about a forged org header? Membership lookup and RLS still control. **Common mistake:** trusting saved chart JSON. **Alternative:** governed materialized cache keyed by auth policy/version. **Exercise:** revoke access between refreshes.
12. **Question:** Why fence dataset versions across cards? **Short answer:** A dashboard must not compare cards computed from different active versions without disclosure. **Deep explanation:** the route records the first version ID and returns 409 if another differs. This is weaker than a single shared database snapshot, but catches a common update race. **Project example:** revenue card from v1 plus profit card from v2 is rejected. **Follow-ups:** Could versions match yet reads differ? Yes, concurrent row mutation would require transactional immutability; how get atomic multi-metric views? Trusted batch analytics transaction. **Common mistake:** assuming sequential requests share a snapshot. **Alternative:** batch query with one snapshot. **Exercise:** simulate an ingestion publish between card calls.
13. **Question:** How would you debug a wrong Delhi contribution card? **Short answer:** Trace the Phase 6 metric definition, currency, period, region scope and source version before inspecting ECharts. **Deep explanation:** the chart only copies a Phase 6 result; errors usually originate in metric semantics, denominator entitlement, data ingestion or filters. Compare response decimal strings to independent SQL in an authorized fixture. **Project example:** Phase 6's contribution metric uses regional/national revenue within one currency. **Follow-ups:** What if national scope is restricted? Fail closed, don't infer it; what if the browser chart differs from API? Inspect number conversion and rendering. **Common mistake:** editing the chart to make the KPI look correct. **Alternative:** table-first debugging. **Exercise:** write an independent SQL reference for a synthetic dataset.
14. **Question:** Why not persist dashboards yet? **Short answer:** Saved/shareable artifacts need their own ACL, retention, revocation and version rules. **Deep explanation:** request-local composition avoids a second authority over private results. Persistence would need resource ownership, migrations, share permission policy and deletion propagation. **Project example:** [dashboard-client.tsx](../../apps/web/src/app/dashboard/dashboard-client.tsx) holds only transient state. **Follow-ups:** Could a URL contain result JSON? It would leak private data; what would a safe saved dashboard contain? Approved query definitions and scope, revalidated on open. **Common mistake:** caching final values by question alone. **Alternative:** ACL-governed saved definitions. **Exercise:** design the dashboard resource table and RLS policy.
15. **Question:** How would you scale 1,000 concurrent dashboard refreshes? **Short answer:** Measure p95 SQL latency and connection pressure, then batch or bound concurrency; don't simply parallelize every card. **Deep explanation:** six sequential cards multiply latency, while fully parallel cards multiply database load. The present route is deliberately bounded at eight and relies on Phase 6 timeouts/quotas. **Project example:** each card executes the Phase 7 graph and Phase 6 SQL. **Follow-ups:** How could a cache be safe? Key by tenant, user/permission revision, dataset version and query parameters, then invalidate; what is backpressure? Limit in-flight work and return a retryable error. **Common mistake:** estimating capacity from unit tests. **Alternative:** precomputed, permission-aware aggregates after measurements. **Exercise:** build a synthetic load test and report p50/p95 plus DB pool usage.
