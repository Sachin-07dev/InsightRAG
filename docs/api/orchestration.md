# Query orchestration API

`POST /api/v1/orchestration/query` requires the existing OIDC bearer token and `X-Organization-ID` header. The [request/response models](../../apps/api/src/insightrag/orchestration/contracts.py) are exported in [OpenAPI](openapi.json). Example request and route behavior are in [the Phase 7 README](../modules/orchestration/README.md).

Request fields: `workspace_id`, `question`, optional `document_resource_ids` (up to 32), optional `dataset_id`, separate `document_question` and `analytics_question` for combined requests, optional `conversation_id`, `region`, `currency`, `year`, `comparison_year`, `chart`, and optional `max_context_tokens`/`max_completion_tokens`. The token fields may only reduce Phase 5's configured limits; no price-based admission guarantee is implied. Resource IDs select candidate scopes but do not grant access. A document-only question with an empty ID list searches currently readable active documents in the authorized workspace, as Phase 5 already does. `chart=true` requires a dataset. A hybrid request without both subquestions yields `clarification` rather than silently decomposing the question.

Success returns `status`, `route`, `answer`, optional unchanged Phase 5 `document`, optional unchanged Phase 6 `analytics`, optional `chart`, `uncertainty`, and `executed_nodes`. `partial` means analytics is verified but document generation was unavailable or Phase 5 abstained. A document resource denial never becomes `partial`. Existing service errors propagate; graph timeout is 504 `orchestration_timeout`. This non-streamed endpoint does not create a dashboard or persist a chart.
