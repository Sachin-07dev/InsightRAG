# OLTP, OLAP and PostgreSQL query planning

**What.** OLTP optimizes many small transactions and current state; OLAP optimizes scans and aggregates. PostgreSQL is row-oriented, transactionally publishes an active dataset version and evaluates current ACL/RLS. [The analytics service](../../apps/api/src/insightrag/analytics/service.py) also runs bounded OLAP-style `SUM`, `COUNT` and `GROUP BY` queries. DuckDB is columnar and runs [one in-memory offline comparison](../../apps/api/src/insightrag/analytics/local.py); no production snapshot bridge exists.

**How.** PostgreSQL parses fixed SQL, plans access paths, applies predicates, computes aggregate groups and returns at most 500 groups. A composite index on `(org_id,resource_id,version_id,currency,transaction_date,region)` supports common scope/date filters, but selectivity, RLS functions, cardinality and table size decide whether an index or scan wins. Verify with `EXPLAIN (ANALYZE, BUFFERS)` on synthetic data under the restricted runtime role; never run an unbounded explain on customer data without approval. A materialized view could accelerate popular aggregates but must preserve each tenant/row policy and active-version invalidation.

**Production.** The service sets 3-second statement timeout and 8 MiB work memory. A 500-group result cap does *not* cap scanned rows; admission, quotas, database metrics and load tests remain necessary. DuckDB's `memory_limit` is an engine setting, not a hard process cap; some operations allocate outside its buffer manager, and spilling can use disk. Its in-process memory and temp-disk behavior need a separate OS/process sandbox before it can hold authorized production snapshots. Compare p95 latency, CPU, buffer reads, temp spills and tenant interference before adding partitioning, a warehouse, or separate analytical workers. See official [DuckDB configuration](https://duckdb.org/docs/stable/configuration/overview), [out-of-memory guidance](https://duckdb.org/docs/current/guides/performance/oom), [PostgreSQL RLS](https://www.postgresql.org/docs/current/ddl-rowsecurity.html) and [exact numeric](https://www.postgresql.org/docs/current/datatype-numeric.html) references.
