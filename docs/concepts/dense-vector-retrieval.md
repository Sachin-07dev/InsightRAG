# Dense vector retrieval

**What/why.** An embedding model maps a text string to a fixed-length numeric vector so paraphrases can be near each other even without shared words. Phase 4 stores 1,536-dimensional document chunk vectors in `ingestion_chunks.embedding`; `retrieval/repository.py` embeds the query through the same configured model and orders authorized active chunks by pgvector cosine distance. The model ID in `document_versions` fences incompatible embeddings. This is approximate semantic retrieval, not proof that a top-ranked chunk answers the question.

**Math/how.** Cosine similarity is `q·d/(||q||||d||)`; cosine distance used here is `1−cosine`. For `q=(1,0)` and `d=(0.8,0.6)`, norms are 1, similarity 0.8 and distance 0.2. Dot product is `Σqᵢdᵢ`; L2 is `sqrt(Σ(qᵢ−dᵢ)²)`. On unit-normalized vectors, `||q−d||²=2−2(q·d)`, so cosine, dot and L2 give equivalent rankings. Without normalization, vector magnitude can change dot/L2 order. Score direction and range differ. A high cosine similarity may still be irrelevant because the training objective, chunk boundaries and business intent differ from exact answerability.

**Implementation/production.** `embedding <=> CAST(:vector AS vector)` matches Phase 4's HNSW `vector_cosine_ops` index. HNSW builds a layered proximity graph; at query time it greedily descends then explores candidates. Larger search effort improves recall at latency cost; build parameters affect index size/time. IVFFlat partitions vectors into lists and probes selected lists; exact scan computes every distance. ACL prefilters can reduce ANN recall, so compare HNSW against exact authorized scans on a labelled corpus. The SQL also constrains org/workspace, active published version, permission and model before candidate text is exposed. A mismatched dimension fails validation; a changed model requires reindex. A safe cache would need model/version/tenant/policy scoping and invalidation; none is enabled. Monitor embedding latency, candidate counts, ANN recall and p95 by tenant. Alternative search services add a second ACL synchronization boundary; migrate only when measured PostgreSQL limits justify it.

**Interview/improvement.** Defend pgvector by the existing transactional provenance and RLS boundary, not a claim it is universally fastest. Be ready to derive cosine/L2 equivalence, explain why ANN recall is measured against exact search, and debug a model-ID mismatch. Tune index/search parameters only against relevant/irrelevant labels and tenant-filtered workloads.
