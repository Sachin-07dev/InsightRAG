# Visualization security boundary

Identity comes from the OIDC bearer token and server-side membership lookup in [dependencies.py](../../apps/api/src/insightrag/security/dependencies.py). The [dashboard endpoint](../../apps/api/src/insightrag/visualization/routes.py) passes scope to Phase 7, which invokes Phase 6's `analyze` with expected workspace ID. Phase 6 checks active resource ACL, uses RLS and current dataset version. The organization header chooses a membership to check; it does not grant one. Any denied card fails the whole response. The browser may ask for a year, region or chart type but cannot set result rows, currency conversions or metric definitions.

The Next.js proxy forwards only required headers/body and declares `no-store`; the API returns `private, no-store`. There is no shared cache, persisted dashboard or link. The token remains in memory, though an XSS bug could still steal it; production browser SSO should replace the manual token field. ECharts uses rich-text tooltip rendering to avoid HTML injection; text from datasets remains untrusted. PNG/SVG exports are created locally after an authorized fetch, but downloaded files cannot be revoked. Production deployment should apply CSP, TLS and an export policy according to sensitivity.

Threat tests: [test_visualization.py](../../apps/api/tests/test_visualization.py) checks that every card invokes the trusted orchestrator, a denial aborts all cards, and version races fail. Existing Phase 6/7 integration tests cover database ACL/RLS; this phase has not run a browser-to-database penetration test. Recheck authorization on every refresh, and never serve old chart data from a server cache keyed only by question.
