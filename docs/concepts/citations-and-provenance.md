# Citations and provenance

A citation ties a response to the **same active document version** and exact chunk that the model saw. `retrieval/context.py` computes a deterministic opaque label from organization, resource, version and position; the response exposes the authorized document/workspace IDs, title, version, locator, position and relevant excerpt. It does not expose object-store keys. The label is stable for that immutable version but is not an authorization credential. A new version gets a new label. A deleted document can leave a historical label in a stored turn, yet resolution must reauthorize and may be unavailable; the API does not offer unrestricted historical source download.

`verify_citations` checks labels are in selected evidence and excerpts are exact substrings of the selected chunks. `revalidate_evidence` rereads each chunk through current RLS and explicit `can_resource`/active-version checks after generation. This blocks a slow model response from releasing evidence that was revoked, deleted or superseded meanwhile. It verifies provenance and access, not semantic support for every sentence. Claim-level citation coverage and accuracy require labelled propositions and a reviewer or independently validated entailment process. “The policy requires finance approval” cites the policy sentence; “sales rose 20%” cannot be supported by a generic policy citation.

To debug a wrong citation, inspect (with authorized diagnostic access) the resource/version/position, actual excerpt, selection order and model's returned label, then check whether the claim is present or inferred. Never manufacture page numbers when a parser produced only a line or table locator. Monitor invalid-label failures and stale-version 409s without logging private excerpts.
