# LangGraph fundamentals in InsightRAG

**WHAT.** LangGraph represents a computation as nodes joined by edges. A [StateGraph](https://reference.langchain.com/python/langgraph/graph/state/StateGraph) node reads state and returns a partial update; `compile()` validates edges and creates an executable graph. `START` and `END` delimit execution. A conditional edge chooses its next node from a finite map. A reducer combines simultaneous writes to one state key, but this project has no parallel branches and needs no reducer.

**WHY.** The Phase 7 requirement asks for an auditable query router, not an open-ended agent. [GraphState](../../apps/api/src/insightrag/orchestration/graph.py) is a `TypedDict`, while API and route decisions use Pydantic runtime validation in [contracts.py](../../apps/api/src/insightrag/orchestration/contracts.py). `TypedDict` helps static checking but does not validate wire input; Pydantic does. The graph expresses termination and source-tool boundaries visibly. Plain Python would remain a viable smaller implementation; LangChain's linear chains fit prompt pipelines better than this branch structure.

**HOW.** [build_graph](../../apps/api/src/insightrag/orchestration/graph.py) adds seven nodes, maps the four route labels to destinations, and compiles once per request. `ainvoke` schedules async nodes and awaits I/O; it does not make SQL or model computation magically parallel. `recursion_limit=8` and a wall-clock timeout bound execution. There is no cycle and no autonomous retry. A failed authorization check raises through the graph. In a hybrid path the SQL node precedes the document node, so state merges are simple replacements rather than concurrent reducer operations.

**Checkpointing and recovery.** A checkpointer snapshots graph state between steps and requires a thread identifier. It is useful for pause/resume and human review, but the state here can contain private evidence. [LangGraph's checkpointer contract](https://reference.langchain.com/python/langgraph/checkpoint) supports asynchronous savers, yet a production saver must additionally bind each thread to user/tenant, encrypt data, enforce retention and deletion, and recheck permissions on resume. Phase 7 therefore compiles without one. A client retry starts a new authenticated request; Phase 5 retains its own scoped conversation history.

**Tools and structured output.** The tool adapters in [routes.py](../../apps/api/src/insightrag/orchestration/routes.py) transform a validated request into Phase 5 `QueryRequest` or Phase 6 `AnalyticsRequest`. No model supplies SQL, resource IDs, role claims or arbitrary tool names. The finite [RouteDecision](../../apps/api/src/insightrag/orchestration/contracts.py) could later validate an LLM classifier, but that classifier is not implemented. For deterministic tasks, model routing would add latency, cost and prompt-injection exposure without a demonstrated benefit.

**Production.** Async FastAPI and `ainvoke` help with concurrent network/database waits; database pool size, provider rate limits and worker capacity still govern throughput. OTel spans and completion logs must exclude raw private text. Parallel graph branches could cut hybrid latency but would need safe reducers and a consistent authorization snapshot. Add them only after real p95 and isolation measurements. The graph is not a security boundary: trusted services and PostgreSQL enforce authorization.

**Interview / improvement.** Be ready to explain: (1) a node returns only changed keys; (2) a reducer is needed only for concurrent writes; (3) `compile` validates shape but not business authorization; (4) a checkpointer can retain revoked content; and (5) a recursion limit caps steps, not CPU or SQL work. A future LLM router needs a labeled evaluation set and a refusal path, while a future durable graph needs tenant-scoped checkpoint governance.
